# Architecture Decision Records

This directory contains Architecture Decision Records (ADRs) for VirtRigaud. ADRs record significant design decisions that are binding on the codebase and should not be re-litigated without reading the relevant ADR first.

## Format

```
# ADR-NNNN: Title
## Status: Proposed | Accepted | Deprecated | Superseded by ADR-XXXX
## Context
## Decision
## Consequences
```

| [0011](./0011-migration-staging-cleanup.md) | Migration staging cleanup through a provider RPC | Accepted | 2026-10-11 | Option A: a new `DeleteStagedDisk` provider RPC, sent to the migration's target `Provider`, deletes the `nfs`/`s3` staged disk after success, on terminal failure (`cleanupPolicy: Always`) and when the `VMMigration` is deleted. The provider derives the object from the migration identity (no key or path on the wire). A failed delete is held (`StagingCleanup=False`, backoff 15 s to 5 min, force-delete releases). Older providers (capability absent / `Unimplemented`) are recorded as left behind once and released. libvirt/vSphere NFS truncate to 0 bytes (libnfs cannot unlink). Amended 2026-10-12: unambiguous NFS staging name (layout v2, recorded per migration), staging digest (no delete after a spec change), 24 h hold for older providers, post-migration cleanup only for migrations this manager completed, and staged-image header checks on every import. Addendum A (rc2, 2026-10-17): a `DeleteLandedDisk` RPC deletes the disk a failed or deleted migration's import landed on the target, unless a VM uses it, with the same `cleanupPolicy` rules. |
| [0012](./0012-proxmox-legacy-unstamped-name-rule.md) | Retiring the Proxmox legacy unstamped-name rule | Accepted | 2026-10-17 | Security review M2 of #393 (R14): an unstamped Proxmox VM named like its owner is accepted by every owner check, so a PVE user with `VM.Allocate` can plant a look-alike at a freed VMID. Proposes A+B: the manager latches `status.ownerStamp` once `Describe` confirms the stamp (`DescribeResponse.owner_check`) and then sends `ObjectIdentity.require_owner_stamp`; legacy VMs are stamped once through `TransferOwner` (default-on, per-Provider opt-out). Phase 1 targets v0.4.1, gated on real-PVE validation; later phases drop the name rule by default and then remove the escape hatch. v0.4.0 ships operator guidance only, and the forged-stamp residual is accepted. Rejects a creation-time cutoff; defers binding to PVE `meta` ctime (the only fix for a copied stamp). No change for vSphere/libvirt (no name rule). |
| [0013](./0013-disk-resize-flow.md) | Disk resize as its own, honest flow | Proposed | 2026-10-23 | R19 (#401 review): a disk size change alone is silently ignored today. `Describe` reports every disk with a stable identity (vSphere backing UUID, libvirt target dev, Proxmox bus key), role and capacity into a new `status.disks`; the manager compares desired with **observed** sizes and sends a new typed `ResizeDisks` RPC (grow-only, per-disk outcome enum, `supports_disk_resize` capability), separate from CPU/memory `Reconfigure`; a `DiskSizeApplied` condition says why when nothing can be applied; clustered grows are checked against host free storage. Seven slices, smallest first. |
| [0014](./0014-migrated-guest-network.md) | A migrated guest keeps its identity and gets working network | Accepted | 2026-10-23 | R36 (lab, v0.4.0-rc4): migrated Ubuntu guests have no network on vSphere/Proxmox targets, and change identity on libvirt targets. cloud-init renders network only for a new instance, and no datasource we can present enables the `boot` event on the first target boot, so a same-instance-id seed with a network-config does not bring the network up. Recommends option B: carry each source NIC's MAC to the target (fixing the silently dropped `spec.networks[].macAddress` and a Proxmox `networks_json` key mismatch that also drops bridge/VLAN) and present the same instance-id (or no datasource when unknown), captured once by a new `DescribeGuestIdentity` RPC; no `local-hostname` is presented. Slice 0 adds a safe-by-default tenant MAC policy (Provider `tenantMACAddresses: Deny`, normalisation, unicast and duplicate checks). Guests that fall to `DataSourceNone` (single-entry `datasource_list`, RHEL with open-vm-tools on vSphere) are a documented caveat. `spec.options.guestIdentity: Preserve\|Fresh` keeps option 2 open. Eight slices. |

## Contributing an ADR

1. Copy the format from an existing ADR.
2. Number it sequentially (NNNN).
3. Set Status to **Proposed** until accepted.
4. Open a PR; move to **Accepted** when merged to `main`.
5. For superseded ADRs, update the old ADR's Status line and link to the new one.
